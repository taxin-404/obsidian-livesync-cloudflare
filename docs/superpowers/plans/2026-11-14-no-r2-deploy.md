# No-R2 Deployment Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let a user deploy and run sync on a Cloudflare account that cannot enable R2, using one documented command that also works from Workers Builds.

**Architecture:** The existing deploy script already builds a temporary reduced config when `BACKUP_ENABLED` is `"false"`. Add a `--no-r2` flag that forces that reduction regardless of the flag in `wrangler.jsonc`, then document the local and Workers Builds commands.

**Tech Stack:** Node.js 22.18+/24.11+, Wrangler 4.45+, `node:test`, TypeScript JSONC parser.

**Spec:** `docs/superpowers/specs/2026-11-14-no-r2-deploy-design.md`

## Global Constraints

- Cloudflare free plan; no new dependencies.
- Do not change the default deployment: `npm run deploy` keeps R2 backups enabled.
- A no-R2 deploy must not delete bucket objects or touch Worker secrets or Durable Object data.
- Existing temporary-config handling stays: copy beside the source, mode `600`, removed in `finally`.
- `BACKUP_ENABLED` values are the strings `"true"` and `"false"`.

## Review Focus

- **Invalid or missing `BACKUP_ENABLED` with `--no-r2`:** the deploy must still succeed because the flag forces backups off; the normal path must keep throwing.
- **`env.dev`:** only the selected environment changes; the top-level config and the other environment stay untouched.
- **Other R2 bindings:** only `BACKUP_BUCKET` is removed; a second bucket binding survives.
- **Wrangler arguments:** `--no-r2` must be consumed by the script, never forwarded to Wrangler.
- **Recovery after a no-R2 deploy:** enabling R2 again must reuse the existing bucket and its objects, with no migration.

- [ ] **Step 3: Implement `noR2` in `deploymentConfig`**

```js
export function deploymentConfig(text, environment = '', { noR2 = false } = {}) {
  const { config, error } = ts.parseConfigFileTextToJson('wrangler.jsonc', text);
  if (error) throw new Error(ts.flattenDiagnosticMessageText(error.messageText, '\n'));
  const selected = environment ? config.env?.[environment] : config;
  if (!selected) throw new Error(`Missing deployment environment: ${environment}`);
  const enabled = selected.vars?.BACKUP_ENABLED;
  if (!noR2 && enabled !== 'true' && enabled !== 'false') {
    throw new Error('Set BACKUP_ENABLED to the string "true" or "false" in the selected configuration.');
  }
  if (!noR2 && enabled === 'true') return null;
  selected.vars = { ...(selected.vars ?? {}), BACKUP_ENABLED: 'false' };
  selected.r2_buckets = (selected.r2_buckets ?? []).filter((bucket) => bucket.binding !== 'BACKUP_BUCKET');
  // An empty list removes deployed cron triggers; omitting it leaves them running.
  selected.triggers = { ...selected.triggers, crons: [] };
  return config;
}
```

Do not change the existing `BACKUP_ENABLED` tests.

Extract the existing validation into an exported function and update the usage text:

```js
export function deployArgs(argv) {
  const [configPath, environment, ...args] = argv;
  if (!configPath || environment === undefined) {
    throw new Error('Usage: deploy-storage.mjs CONFIG ENV [--no-r2] [Wrangler deploy options]');
  }
  if (args.some((arg) => /^(--config|--env|--var|-c|-e)(=|$)/.test(arg))) {
    throw new Error('Set configuration, environment and variables in the deployment config, not extra Wrangler options.');
  }
  return {
    configPath,
    environment,
    noR2: args.includes('--no-r2'),
    wranglerArgs: args.filter((arg) => arg !== '--no-r2'),
  };
}
```

- [ ] **Step 1: Rewrite "Deploy without R2" in `docs/backup-recovery.md`**

Keep the existing `wrangler.deploy.jsonc` route as the custom-config option, and add the flag above it. State all of these explicitly:

- R2 needs an enabled billing profile; some countries and students cannot provide an accepted card.
- Sync, the connection page, and the MCP Worker work without R2; only scheduled and manual backup/restore need it.
- Local command: `npm run deploy:no-r2`.
- Workers Builds deploy command: `node scripts/deploy-storage.mjs wrangler.jsonc "" --no-r2`.
- Dev: `node scripts/deploy-storage.mjs wrangler.jsonc dev --no-r2`.

- Keep independent exports, because there is no server-side backup.
- Existing bucket objects are not deleted; enabling R2 later means restoring the flag and redeploying with `npm run deploy`.
- Calling `wrangler deploy` directly bypasses the flag.
